# 📧 Mailing Service – Инструкция по установке и запуску

Сервис для управления email-рассылками с авторизацией, ролевой моделью, кешированием и фоновыми задачами (Celery).

---

## 🚀 Требования

- **Python** 3.10 или выше  
- **Redis** (для Celery брокера и результатов) – рекомендуется, но можно использовать файловый бэкенд для тестов  
- **Django** 6.1 (или последняя стабильная)

---

## 📦 Установка

### 1. Клонирование репозитория
```bash
git clone <url-репозитория>
cd mailing_service
```

### 2. Создание виртуального окружения
```bash
python -m venv venv
# для Windows:
venv\Scripts\activate
# для Linux/Mac:
source venv/bin/activate
```

### 3. Установка зависимостей
Создайте файл `requirements.txt` со следующим содержимым:
```
Django>=6.1
celery>=5.3
redis>=5.0
pytz
django-celery-beat  # опционально, если планируете хранить задачи в БД
```
Установите:
```bash
pip install -r requirements.txt
```

### 4. Настройка переменных окружения (секретные ключи)
Создайте файл `.env` в корне проекта и пропишите:
```
SECRET_KEY=ваш-секретный-ключ
DEBUG=True
EMAIL_HOST_USER=ваш-email@example.com
EMAIL_HOST_PASSWORD=ваш-пароль-приложения
```
В `settings.py` замените `SECRET_KEY` на чтение из переменных:
```python
import os
from dotenv import load_dotenv
load_dotenv()
SECRET_KEY = os.getenv('SECRET_KEY')
```

### 5. Настройка почты (SMTP)
В `settings.py` замените `EMAIL_BACKEND` на реальный бэкенд:
```python
EMAIL_BACKEND = 'django.core.mail.backends.smtp.EmailBackend'
EMAIL_HOST = 'smtp.yandex.ru'          # или smtp.gmail.com
EMAIL_PORT = 465
EMAIL_USE_SSL = True
EMAIL_HOST_USER = os.getenv('EMAIL_HOST_USER')
EMAIL_HOST_PASSWORD = os.getenv('EMAIL_HOST_PASSWORD')
DEFAULT_FROM_EMAIL = EMAIL_HOST_USER
```
Для тестов можно оставить `console.EmailBackend` – письма будут выводиться в консоль.

### 6. Применение миграций
```bash
python manage.py makemigrations
python manage.py migrate
```

### 7. Создание суперпользователя
```bash
python manage.py createsuperuser
```

### 8. Создание необходимых групп
В админке Django (через суперпользователя) создайте группу `managers`.  
В неё нужно добавлять пользователей, которым разрешены все операции CRUD.

Также группа `users` создаётся автоматически при регистрации, но её можно создать заранее:
```bash
python manage.py shell
```
```python
from django.contrib.auth.models import Group
Group.objects.get_or_create(name='users')
```

## 🏃 Запуск

### 1. Запуск Redis (если используется)
```bash
redis-server
```

### 2. Запуск Django-сервера (в отдельном терминале)
```bash
python manage.py runserver
```

### 3. Запуск Celery Worker (в другом терминале)
```bash
celery -A mailing_service worker --loglevel=info
```

### 4. Запуск Celery Beat (в третьем терминале)
```bash
celery -A mailing_service beat --loglevel=info
```
Beat будет каждую минуту проверять и отправлять рассылки, у которых наступило время старта.

## 👥 Роли и доступы

- **Анонимный пользователь** – может зарегистрироваться, войти, восстановить пароль.
- **Обычный пользователь** (группа `users`) – после входа видит только главную страницу со статистикой (активные рассылки, количество клиентов). Доступ к управлению **запрещён**.
- **Менеджер** (группа `managers` или суперпользователь) – имеет полный доступ:
  - CRUD для получателей (`/recipients/`)
  - CRUD для сообщений (`/messages/`)
  - CRUD для рассылок (`/mailings/`)
  - Просмотр статистики (`/stats/`)
  - Ручной запуск рассылки из списка (`/mailings/<id>/run/`)

**Назначение роли менеджера:** через админку Django (`/admin/`) – выберите пользователя, добавьте в группу `managers`.

## 🧪 Тестирование функционала

1. **Регистрация** – `/register/`
2. **Вход** – `/login/`
3. **Восстановление пароля** – `/password-reset/` (письма приходят на почту, если настроен SMTP)
4. **Создание получателя** – `/recipients/create/`
5. **Создание сообщения** – `/messages/create/`
6. **Создание рассылки** – `/mailings/create/` (задайте интервал времени)
7. **Ручной запуск** – нажмите «Запустить» у нужной рассылки в списке (если текущее время входит в интервал)
8. **Автоматический запуск** – если запущен Celery Beat, рассылка будет отправлена автоматически в указанное время
9. **Статистика** – `/stats/` показывает общее количество и успешность попыток

## 🗂 Структура проекта (кратко)

- `mailing/` – основное приложение
  - `models.py` – Recipient, Message, Mailing, Attempt
  - `views.py` – все представления с разграничением доступа
  - `forms.py` – формы с валидацией времени
  - `tasks.py` – Celery-задачи (отправка и проверка рассылок)
  - `utils.py` – функции кеширования статистики
  - `templates/mailing/` – все HTML-шаблоны
- `mailing_service/` – настройки проекта
  - `settings.py` – конфигурация (база, кеш, Celery, почта)
  - `celery.py` – инициализация Celery

## ⚙️ Дополнительные настройки

- **Кеширование** – используется `LocMemCache` (по умолчанию). Для продакшена лучше использовать Redis или Memcached.
- **База данных** – по умолчанию SQLite. Для продакшена рекомендуется PostgreSQL.
- **Логирование** – можно добавить файловые логи для отслеживания отправок.

## ❓ Часто задаваемые вопросы

**Q:** Почему при ручном запуске выходит ошибка *«Отправка запрещена: текущее время вне разрешённого диапазона»*?  
**A:** Это ожидаемое поведение – вы пытаетесь запустить рассылку до её начала или после окончания. Создайте рассылку с интервалом, включающим текущий момент.

**Q:** Письма не доходят на почту, хотя в консоли есть текст.  
**A:** Проверьте настройки SMTP и пароль приложения. Убедитесь, что `EMAIL_BACKEND` установлен на `smtp`.

**Q:** После выхода из аккаунта я всё ещё вижу кнопки меню и получаю 403.  
**A:** Очистите кеш страниц (уберите `@cache_page` для вьюх, зависящих от пользователя). В проекте уже исправлено.
